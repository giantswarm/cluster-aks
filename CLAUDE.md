# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this repo is

`cluster-aks` is a Giant Swarm Helm chart (`helm/cluster-aks`) that provisions an AKS workload cluster through Cluster API, using CAPZ's **ASO-based** CRDs. It is the AKS counterpart of `cluster-aws`, `cluster-azure`, etc., and is owned by team Phoenix.

## Commands

```bash
# Render locally. The `cluster` subchart is vendored as a .tgz in helm/cluster-aks/charts/ (gitignored);
# run `helm dependency update helm/cluster-aks` after bumping it in Chart.yaml or on a fresh clone.
helm template test-wc helm/cluster-aks -f helm/cluster-aks/ci/ci-values.yaml

# The other ci/test-wc-*-values.yaml files are partial overlays and must be layered on ci-values.yaml
# (they don't set global.managementCluster).
helm template test-wc helm/cluster-aks -f helm/cluster-aks/ci/ci-values.yaml -f helm/cluster-aks/ci/test-wc-byo-vnet-values.yaml

# Lint with chart-testing (docker + architect required)
make lint-chart APPLICATION=cluster-aks

# Schema tooling (values.schema.json is the source of truth)
make normalize-schema   # schemalint normalize
make validate-schema    # schemalint verify --rule-set=cluster-app
make generate-values    # regenerate values.yaml from the schema
make generate-docs      # regenerate helm/cluster-aks/README.md from the schema
```

There are no unit tests. Verification is rendering the chart against the `ci/` values files. On PRs, CI posts Helm render diffs, checks the schema and changelog, and runs the `cluster-test-suites` E2E tests (AKS `standard` and `upgrade` suites) when someone comments `/run cluster-test-suites`. That trigger is already in the PR template and the release PR body. CircleCI publishes the chart to `cluster-catalog` / `cluster-test-catalog`.

## Schema-first values

`values.yaml` starts with `# Auto-generated by helm-values-gen, do not edit!`. To add or change a value, edit `values.schema.json`, then run `make normalize-schema validate-schema generate-values generate-docs`. Commit all three files: the schema, `values.yaml`, and the chart README.

## Architecture

### Two-chart split

This chart depends on the provider-agnostic `giantswarm/cluster` subchart (`Chart.yaml`). The subchart renders the CAPI `Cluster`, `MachinePool`s, and the default platform apps as Flux HelmReleases. This chart renders only the CAPZ/ASO-specific CRs. The two charts talk through `cluster.providerIntegration` in `values.yaml`, a contract that tells the subchart which infra kinds to reference and which of *this* chart's named templates to include:

- `controlPlaneResource.provider: external`: AKS owns the control plane, so no KubeadmControlPlane is rendered. `infrastructureMachineTemplate*` is required by the subchart's schema but unused; it points at the `noop` template.
- `machinePool.bootstrap.templateName: azureMachinePoolBootstrap` renders `dataSecretName: ""` because AKS bootstraps kubelet. The leading blank line in that template is intentional (the subchart includes it with `indent 8`).
- `clusterAnnotationsTemplateName: azureClusterAnnotations` adds the location and subscription annotations to the Cluster CR.
- `machineHealthCheckResourceEnabled: false`: AKS remediates nodes itself.
- `apps.<app>.configTemplateName: AKS…HelmValues`: the subchart pulls per-app AKS overrides from the named templates in `templates/helmreleases/_*.yaml`. The exception is `azure-aks-extras-helmrelease.yaml`, which this chart renders itself (an OCIRepository plus a HelmRelease).

User-facing knobs live under `global.*`, which Helm shares with the subchart. The subchart reads `global.nodePools`, `global.release`, `global.metadata`, and so on directly. A named template referenced from `providerIntegration` must exist in `_helpers.tpl` or `templates/helmreleases/`, otherwise rendering fails inside the subchart.

### CRs rendered here (`templates/list.yaml`)

Each CR embeds Azure Service Operator resources under `spec.resources`:

- `AzureASOManagedCluster`: ASO `ResourceGroup`, plus a `VirtualNetwork` and `VirtualNetworksSubnet` unless the VNet is bring-your-own (BYO). BYO is on when `global.connectivity.network.vnet.subnetArmId` is set; see the `cluster-aks.vnet.byo` helper.
- `AzureASOManagedControlPlane`: ASO `ManagedCluster`. The Kubernetes version comes from the subchart's `cluster.component.kubernetes.version`, which resolves through the Release.
- `AzureASOManagedMachinePool`: one per `global.nodePools` entry (falling back to `workers.defaultNodePools`). Each wraps a `ManagedClustersAgentPool` that points at either the chart-created subnet CR or the BYO subnet ARM ID.
- An ASO credentials `Secret`, rendered only when `global.providerSpecific.asoAuthenticationSecretName` is unset. It uses Helm `lookup` on the `AzureClusterIdentity` (`global.providerSpecific.azureClusterIdentity`) and fails if that identity is missing. Offline renders therefore need `asoAuthenticationSecretName` set, which is why every `ci/` file sets it.

### Validation layers

- `templates/required.yaml`: `required` checks for location, subscriptionId, organization, managementCluster, and baseDomain.
- `templates/_validation.tpl`: cross-field rules. At least one pool must have `mode: System`; the VNet CIDRs must be set unless the VNet is BYO, and `vnet.name` must not be combined with BYO; `disableLocalAccounts` requires `aadProfile.managed`.
- `values.schema.json`: per-field types and constraints.

## Conventions

- Name CRs with `cluster-aks.resource.name`. It mirrors the subchart's `cluster.resource.name`, and CAPI resolves refs by name. Use `cluster-aks.resourceGroup.name`, `cluster-aks.vnet.name`, and `cluster-aks.subnet.crName` instead of computing names inline.
- Every embedded ASO resource carries the `serviceoperator.azure.com/credential-from` annotation, wrapped in `with (include "cluster-aks.aso.credentialSecretName" .)`. Follow the same pattern for new ones.
- Keep `helm.sh/resource-policy: keep` on `AzureASOManagedCluster`, `AzureASOManagedControlPlane`, and the credentials Secret, so `helm uninstall` doesn't delete the Azure resources.
- Add user-visible changes to `CHANGELOG.md` under `[Unreleased]` (Keep a Changelog format). CI validates the changelog.
- Don't hand-edit files generated by devctl: `Makefile`, `Makefile.gen.*.mk`, `.github/workflows/zz_generated.*`, `.cursor/rules/zz_generated.*`, `.nancy-ignore.generated`. The same goes for `values.yaml` and the chart README (see above).
